# Nexus Memory 产品定位

> 决策日期：2026-08-06

## 定位声明

**Nexus 是带时间轴的长期记忆系统。**

一句话版本：

> CLAUDE.md 告诉你现在的样子。Nexus 记得它是什么时候变成现在这样的。

## 收敛过程（为什么是这个定位）

### 排除的定位

1. **通用跨会话记忆** —— 被 CLAUDE.md / soul.md / agent.md 静态文件覆盖（免费、本地、零配置）。"记住偏好/背景/规则"不是差异化。
2. **"翻旧账"**（回忆有确定答案的讨论）—— 低频伪痛点：确定答案会自己沉淀到代码、文档、CLAUDE.md，不需要对话记忆。

### 确立的差异化

记忆的核心价值是回答**带时间坐标的问题**——答案不在任何文档里，只存在于记忆的时间轴上：

- **时效判断**："三个月前定的技术选型，现在还生效吗？"（取决于"何时定的、中间有没有被推翻"）
- **状态追踪**："上上周说的那件事，最后提到是什么时候？"
- **时间线重建**："我们是什么时候开始用这套方案的？"（最早提及时间）
- **变化检测**："他对 X 的态度是什么时候从 A 变成 B 的？变了多少次？"

## 排他性（为什么别人答不了）

| 方案 | 时间轴 | 失效原因 |
|------|--------|----------|
| CLAUDE.md / soul.md | 无 | 当前状态快照——只知道"现在"，不知道"何时变成现在" |
| LLM 蒸馏（mem0 / TencentDB Agent Memory） | 丢 | 蒸馏时时间坐标丢失，只剩当前画像（Persona），无历史 |
| **Nexus** | **有** | 全量 raw chunk + event_time——完整时间线存在 |

关键组合：**零 LLM + 全量存储**使完整时间线在经济上首次可行——蒸馏方案为省 token 必然丢节点，时间线拼不齐，因而永远回答不了"什么时候变的"。

## 对技术路线的影响

- **temporal 从"短板"升级为"产品本体"**：LoCoMo temporal 40.8% → 目标 70%+，修复是产品成立的前提，不再是追 benchmark 分数的补差
- **ingest 侧时间归一化**（相对时间词 → 绝对日期，注入 reference_date）为第一优先级
- **查询侧**：时间坐标式查询（"X 什么时候发生"、"X 之前是什么"、"最后提到 X 是什么时候"）

## 边界（不做的事）

- 不解决"确定答案"的记忆——答案会自我沉淀到工作产物，无需对话记忆
- 不做 LLM 蒸馏——丢时间坐标，与定位直接冲突
- 不面向"第一天新手"做宣传——时间性记忆的价值在持续使用数周后显现（CLAUDE.md 装不下、时间查询真实发生之时）
