# Nexus Memory 定位 2：带时间轴的代码库记忆

> 决策日期：2026-08-06
> 关系：定位 1（[positioning.md](positioning.md)）的垂直特化——同一产品本体，代码域场景

## 定位声明

**Nexus 帮助 agent 理解整个代码库——不是它的静态结构，而是它怎么变成现在这样的。**

一句话版本：

> CLAUDE.md 告诉你代码现在长什么样。Nexus 记得代码是什么时候变成现在这样的。

## 与定位 1 的关系

定位 2 不是独立支柱，是定位 1（带时间轴的长期记忆）在代码域的实例：

- 同一产品本体：时间轴记忆
- 同一套技术短板：时间归一化——temporal 40.8% 是共享短板，"三个月前引入的""上次重构的时候"在代码讨论和 commit message 里同样存在
- 差异只在 ingest 源：对话 raw chunk → git 事件流 + 代码决策讨论

## 收敛过程（为什么是这个定位）

### 启发

code graph（静态代码索引：符号、引用、依赖）——"帮助 agent 理解代码库"的现有方案。

### 排除的定位

**静态代码图**（Sourcegraph/SCIP/LSIF、Cursor、tree-sitter、Serena）——已解决的问题域，确定性解析器做得很好；nexus 的正则实体提取不是符号解析器，正面刚必输。若做成"又一个代码索引器"，与定位 1 被 soul.md 否决同理。

### 确立的差异化

"理解整个代码库"拆成两半：

- **静态结构**："这个函数调谁、谁引用它"——已解决，不碰
- **代码记忆**："代码为什么长这样"——无人解决：

  - 变更时间轴："这个函数什么时候引入的？"
  - 决策语义："当时为什么选 X 不选 Y？"（git 无语义，对话记忆易失）
  - 变化检测："这个模块什么时候开始膨胀的？"

关键组合：**git 提供"何时改"的结构化事件流（commit = event_time），对话提供"为何改"的语义记忆**——融合成一条轴。

## 排他性（为什么别人答不了）

| 方案 | 时间轴 | 语义 | 失效原因 |
|------|--------|------|----------|
| 静态 code graph（Cursor / Serena / Sourcegraph） | 无 | 无 | 当前结构快照——不知道"为什么长这样" |
| git log / blame | 有（结构） | 无 | 知道"何时改"，不知道"为何改" |
| CLAUDE.md / 代码注释 | 无 | 有 | 语义有沉淀但无时间轴 |
| **Nexus（定位 2）** | **有** | **有** | git 事件流 + 对话决策融合成一条时间轴 |

## 技术方案

| 方案 | 内容 | 工作量 | 重叠风险 |
|------|------|--------|----------|
| **A（推荐）** | git 事件流 ingest + 对话决策记忆融合；不做符号索引 | 小 | 低——静态结构留给现有工具 |
| B | A + tree-sitter 符号图（函数/类/模块节点进实体图） | 中 | 中——与 Serena 重叠 |
| C | 不做代码域 | 零 | ——— |

## 实施顺序

**先定位 1，后定位 2**：

- 定位 2 的任何实现都包含定位 1 的基座（时间归一化、时间坐标查询）——不存在"跳过硬做"
- 先做定位 1 使定位 2 变成"已有能力 + git 事件流"小增量
- 定位 1 有现成验证闭环（LoCoMo，40.8% → 70%+）；定位 2 的评测需另行发明（git 历史问答集）

## 边界（不做的事）

- 不做静态符号索引——已解决的问题域，正面竞争必输
- 不做代码问答"翻旧账"——确定答案会沉淀到代码/注释，无需对话记忆
- 关键风险：语义记忆厚度依赖 agent 接入侧把代码决策讨论写入 nexus——接入点不解决，nexus 只剩 git 数据，与 `git log --graph` 无差别
